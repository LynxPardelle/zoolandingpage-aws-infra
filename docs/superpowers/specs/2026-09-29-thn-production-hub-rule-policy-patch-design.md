# THN production Hub rule policy patch

Date: 2026-09-29. Scope: the production deployment identities stack in AWS account `765932874577`, `us-east-1`. This operation repairs the CloudFormation execution role's access to the three EventBridge rules in the Content Hub production state template. It does not deploy Content Hub.

## Incident and decision

Content Hub state execution [36632270213](https://github.com/LynxPardelle/zoolanding-content-hub/actions/runs/36632270213) rolled back when `events:DescribeRule` was denied for `zoolanding-content-hub-pr-ThnContentHubV2PreparedOr-3oPnJWQJPmCK`. The current managed policies use the full stack and logical ID in their ARN patterns, while CloudFormation generated a shorter name. The same 25-character stack prefix and 25-character logical prefix are present on the three existing TEST rules. A read-only IAM simulation confirmed `implicitDeny` for the actual failed ARN; simulation of the proposed policies permits all nine required EventBridge actions on each of the three concrete rule ARNs.

The local manifest changes only the EventBridge resource patterns in `HubCfnNativePolicy2` and `HubCfnNativePolicy3`. The current protected identities workflow cannot apply this change: its `bootstrap` composer rejects modifications to existing resources, and `trust-patch` only modifies three role trust policies. Add a third manual scope, `hub-rule-policy-patch`, to that workflow and its native release tool. Use CloudFormation to update the existing policies in place. Never edit policy versions directly with IAM or use an unprotected workflow.

## Considered approaches

- A direct IAM policy-version update would bypass CloudFormation ownership and retained change-set review, so it is excluded.
- Reusing `bootstrap` would fail on existing resources; widening its change allowance would weaken the general identities release. The dedicated scope keeps the exception limited to the two known policies.
