The protected deployment-identities workflow gains an `api-runtime-role-patch` review scope. It allows one retained Lambda-trusting IAM role Add and two exact API IAM policy Modify changes, with unchanged owner-pool and resource identities. The private-frontdoor preflight now rejects the closed all-zero Origin digest before any publishing or change-set call.

The same proof passed with live AWS CLI responses. A separate proposed-policy simulation confirmed `iam:PassRole` on the future external role only for `lambda.amazonaws.com`; the current API execution role remains denied until this patch is applied.
